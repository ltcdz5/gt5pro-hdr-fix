# 技术说明

## 它拦截的是什么

DSPP 的 **3D gamut 表**（17×17×17，每项 12 bit，整表 39536 字节）。

进入 HDR 模式时，驱动调用：

```
reg_dmav2_setup_dspp_3d_gamutv43(struct sde_hw_dspp *ctx, void *cfg)
```

其中 `cfg->payload` 指向驱动缓存的表数据，`cfg->len = 39536`。
本模块用 kprobe 挂在这个函数上，把 payload 的内容整体替换成校正后的表。

之所以能持久：`payload` 指向的是驱动自己缓存的 blob（不是栈上临时结构），
改它就是改驱动状态；而 HDR 期间驱动不会再次重写，所以一次替换管整个会话。

## 为什么只影响 HDR：白名单

**默认放行，只有明确认出的才动。**

```
if 指纹 == 横屏HDR(0xb9b4c7e9)   -> 用横屏手调表替换
else if 蓝明显偏低(B/R < 0.97)   -> 用竖屏补蓝表替换
else                             -> 原样放行（含 SDR）
```

这是本项目踩过最大的坑：

| 曾经的做法 | 后果 |
|---|---|
| 黑名单：排除 SDR 指纹就替换 | SDR 指纹也会变，漏一个就把整个桌面染蓝 |
| 黑名单：白点蓝低就补 | SDR 也可能蓝低，误伤 |

**教训：识别必须做成白名单。黑名单漏一项就出事，而且是在用户桌面上出事。**

实测 SDR 桌面 822 次调用全部走 else 分支，零误替换。

## 表的编码

```
struct drm_msm_3d_gamut {
    u64 flags;
    u32 mode;                  // 必须为 1（mode 17）
    u32 scale_off[3][16];
    struct drm_msm_3d_col col[4][1229];   // 偏移 204，共 39328 字节
};

struct drm_msm_3d_col {
    u32 c2_c1;   // 高 16 位 = G，低 16 位 = B
    u32 c0;      // R
};
```

**通道映射：c0 = R，c1 = B，c2 = G。**

注意 **c1 是蓝，不是绿**——这一点搞错会让所有调色都往绿色跑，
是本项目踩过最大的第二个坑。确定方法：给三个通道不同的增益，拍屏幕比对。

网格索引：

```
n = g*289 + b*17 + r      // r 变化最快
entry = n / 4             // 项内偏移
table = n % 4             // 表偏移
地址 = COL_OFF + (n/4)*8 + (n%4)*1229*8
```

## 校正曲线

### 横屏（手调，逐通道随电平）

```
gain(x) = a + b * (x / 4095)
out    = clamp(x * gain(x))
```

| 通道 | a（中段） | b | 白点 |
|---|---|---|---|
| R | 0.700 | -0.110 | 0.590 |
| G | 0.755 | -0.135 | 0.620 |
| B | 1.030 | -0.280 | 0.750 |

思路：面板偏暖，但低端和高端的偏移量不同，所以用一条随电平的直线去贴。
固定增益会把白点一起拉偏，表现为"要么黄要么青"。

### 竖屏（自动）

竖屏 HDR 表的白点蓝通道比红低约 5.4%（`4074/3852/4095`），
所以只需要把 B 通道整体抬 12%：

```
B *= 1.12
```

## 重新生成表

横屏：

```bash
python3 tools/gain5.py 0.70 -0.11 0.755 -0.135 1.03 -0.28 out.bin
```

竖屏：

```bash
python3 tools/gain_port.py 112 base_portrait.bin out.bin
```

## 调试接口

```bash
su -c 'cat /proc/sdehdrstat'          # 命中统计 + 最后一次的表指纹/白点
su -c 'cat /proc/sdehdrlut_land > /sdcard/land.bin'
su -c 'cat /sdcard/new.bin > /proc/sdehdrlut_land'   # 换表（下次 HDR 切换生效）
```

`/proc/sdehdrstat` 输出示例：

```
calls=822 land=0 port=0 other=822 fp=0x8777be4f white=4045/4095/4092 en=1
```

- `calls` 总调用次数
- `land` / `port` 横屏/竖屏表命中次数
- `other` 原样放行次数（SDR 应全部落在这里）
- `fp` / `white` 最后一次见到的表指纹与白点

## 调试技巧

想知道某个场景到底用了哪些表，可以写一个只记录不修改的探针
（见开发记录里的 sidecar51），按"首次出现"打印指纹和白点。
比猜测快得多。

注意：**热路径上的 kprobe 绝对不能带 printk**，会 printk 风暴把系统拖死。
需要观测时用计数器，卸载时一次性打印。
